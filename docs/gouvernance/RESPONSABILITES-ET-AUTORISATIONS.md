# Responsabilités et autorisations — Observatoire Mondial

## 1. Objet

Ce document précise les règles d'autorisation applicables aux décisions
éditoriales, aux modifications techniques, aux données et aux contenus
d'Observatoire Mondial.

## 2. Responsable du projet

JJCK est le fondateur et responsable du projet.

Les décisions structurantes concernant l'identité, la stratégie,
les règles éditoriales, les partenariats et l'évolution du projet
relèvent de sa responsabilité, sous réserve des droits et obligations
applicables.

## 3. Principe de moindre privilège

Chaque personne ou outil ne doit disposer que des accès nécessaires
à la mission qui lui a été confiée.

Les accès doivent être réévalués lorsque les responsabilités changent
ou qu'une collaboration prend fin.

## 4. Actions nécessitant une autorisation adaptée

Selon leur nature, les actions suivantes nécessitent une autorisation
explicite ou une validation appropriée :

- suppression ou remplacement de fichiers importants ;
- changement de branche ou fusion de branches ;
- publication d'un contenu sensible ;
- transfert de données ;
- accès à des données privées ;
- modification des paramètres de sécurité ;
- ajout d'un service externe ;
- dépense ou engagement financier ;
- accord de partenariat ;
- modification des licences ;
- utilisation d'une création appartenant à un tiers ;
- intégration avec un autre projet ;
- automatisation d'une action à conséquence importante.

## 5. Limites des automatisations

Un script ou un assistant peut préparer une action autorisée, effectuer
des contrôles prévus et présenter des résultats.

Il ne doit pas considérer une proposition comme une autorisation
de supprimer, publier, transférer, fusionner ou engager le projet.

Les actions destructives doivent être précédées d'un contrôle adapté
et d'une sauvegarde lorsque cela est pertinent.

## 6. Publication éditoriale

Les contenus doivent être vérifiés avant publication.

Les sujets sensibles, les allégations graves, les informations privées
et les contenus présentant un risque juridique doivent faire l'objet
d'un examen renforcé.

Une automatisation ne doit pas contourner les règles de validation.

## 7. Modifications techniques

Avant toute modification importante :

1. identifier les fichiers concernés ;
2. examiner les dépendances ;
3. sauvegarder les éléments nécessaires ;
4. définir le résultat attendu ;
5. réaliser uniquement les opérations autorisées ;
6. tester les fonctions concernées ;
7. documenter les résultats et les limites.

## 8. Preuve d'autorisation

Pour les décisions importantes, conserver si possible la date,
l'objet, l'auteur de l'autorisation et le périmètre autorisé.

Ne pas inventer une approbation ou déduire une permission du silence
d'une personne.

## 9. Révocation

Les autorisations peuvent être limitées, modifiées ou retirées par
la personne compétente.

Les accès techniques doivent ensuite être ajustés et contrôlés.

## 10. Traçabilité

Les actions importantes doivent être documentées avec leur résultat réel.

Un ordre donné, une commande préparée ou une modification proposée
ne doit pas être présenté comme une action exécutée.
